# 交通目标检测与跟踪系统

本项目是一个本地 PyQt5 桌面原型，使用现有算法项目的检测器、ByteSort / ByteTrack 跟踪器和可选的轨迹后处理。窗口提供画面预览、检测框和轨迹、当前帧目标数量、置信度、坐标、目标选择及结果保存。

## 启动桌面系统

在带图形桌面的机器上，使用安装了 PyQt5 和原算法项目依赖的 Python 环境：

```bash
cd /home/lzb/object-detection-tracking
python desktop.py
```

桌面程序自动启动仅监听本机的任务服务，关闭窗口时停止该服务。可以通过 `TRACKING_ALGORITHM_ROOT` 指定原算法项目路径，`TRACKING_PYTHON` 指定执行算法的 Python；默认使用 `/home/lzb/Yolov7-tracker-2.1 (2)` 和当前 Python。需要原项目的 PyTorch、OpenCV、Ultralytics 和跟踪依赖，不自动下载权重。

## 使用

- **打开图片 / 视频**：选择文件后自动提交任务。图片输出结果图；视频处理期间显示最新帧，完成后可保存结果视频及轨迹 TXT。
- **打开文件夹**：将文件夹内的图片按名称排序，逐张创建独立检测任务，可在任务记录中切换。它们不是连续视频，不跨图片维持目标 ID。
- **打开摄像头**：使用运行桌面程序的电脑上 OpenCV 摄像头设备 0。停止后保存已处理视频。设备不可用时查看运行日志。
- **参数设置**：选择权重、跟踪器、设备，设置检测框、轨迹、置信度和交并比等。设置在任务开始时生效。RF-DETR 为端到端检测器，不使用交并比参数。
- **检测结果**：表格和数量反映预览的当前帧，点击表格行或选择目标可查看坐标。车辆数量为汽车与卡车之和；累计轨迹 ID 数不是实时目标数量。
- **保存画面 / 轨迹 TXT**：结果保存在独立任务目录，也可以另存到指定位置。视频使用 MP4V 编码；如播放器不兼容，可使用支持 MP4V 的本地播放器。

程序按实际推理速度处理视频，画面显示最新处理帧，预览刷新频率不保证逐帧播放。摄像头帧率由设备和模型速度决定。只对 COCO person、car、truck 三类进行检测跟踪。单帧用时是检测、关联和绘制的处理时间，包含首次模型初始化之外的帧内开销，不是标准性能基准。

## 检测器与轨迹后处理

支持现有 YOLO、RT-DETR 和 RF-DETR Large 权重。RF-DETR 使用原项目 `.venvs/rfdetr/bin/python` 隔离环境及适配器，需要选择 GPU 0；其输入尺寸由 RF-DETR 模型决定。其他检测器使用界面选定的 CPU/GPU 和输入尺寸。

视频任务可选 B → C → A → D 顺序离线后处理：B 为时序 Transformer 框残差优化，C 为 RF-DETR 外观和运动轨迹连接，A 为轨迹评分与缺口补全，D 为边界可靠性控制。C 需要 GPU 和 RF-DETR 隔离环境。处理结果仅作用于汽车轨迹。图片与摄像头不支持离线后处理；先关闭这些选项再启动。

后处理使用原项目 KITTI/RF-DETR 权重和配置，其他检测器或场景仅用于原型演示。系统无法核验上传视频与训练序列是否重叠，因此视频工作流关闭了 A/C 的序列重叠检查；不能据此宣称无数据泄漏或作为论文评测结果。视频后处理完成后重新绘制结果视频；处理期间显示的是在线跟踪结果。

每次任务保存在 `runtime/jobs/<任务ID>/`，包括输入、运行配置、日志、画面和轨迹 TXT。启用后处理时额外保留原始轨迹、各阶段结果和处理记录。轨迹 TXT 为 `frame,id,x,y,width,height,score,class,-1,-1`，帧号从 1 开始，类别为 COCO 编号。不会修改原算法项目和历史实验结果。任务顺序执行；服务结束时未完成任务会中断。

## 可选：网页界面

运行 `python server.py`，浏览器打开 <http://127.0.0.1:8000>。该界面同样只在本机监听，不具备多用户认证；摄像头指服务器所在电脑上的设备 0。
